CUIDAR+ — AJUSTES DE PIN, CELULAR E AVISOS
Projeto Firebase: cuidarmais-e1445
Site: https://kleivsonsilva.github.io/CuidarMais/

O QUE MUDA
1. PIN independente da sessão do responsável, validado no servidor.
2. Interface para celular, com Conta na navegação inferior, campos e botões
   ajustados, menus sem largura fixa e respeito à área de gestos do telefone.
3. Sem mensagens rotineiras de conexão, envio ou salvamento no rodapé.
   Erros que exigem ação continuam visíveis para não ocultar perda de dados.

O PACOTE TEM DUAS PASTAS
- site: arquivos que você envia ao GitHub, substituindo os anteriores.
- servidor: funções e regras que você publica no Firebase.

IMPORTANTE SOBRE O PIN
Só enviar os arquivos ao GitHub NÃO ativa o PIN independente. É obrigatório
publicar as funções abaixo. As funções de produção do Firebase exigem plano
Blaze, com faturamento por uso. Nenhuma mudança de plano foi feita por aqui.
Confira os custos no console antes de ativar. Os ajustes de celular e os avisos
ocultos funcionam com a atualização dos arquivos do site.

A. PUBLICAR O SERVIDOR (UMA VEZ)
1. No Firebase, confirme que selecionou cuidarmais-e1445, com Authentication
   por e-mail/senha e banco Firestore (default) já criados.
2. Verifique se aceita usar o plano Blaze para publicar Cloud Functions.
   Essa decisão e a vinculação de faturamento são feitas por você no console.
3. Instale Node.js 22 LTS pela página oficial https://nodejs.org/
4. Abra o PowerShell dentro da pasta servidor extraída deste pacote.
   No Explorador de Arquivos, entre em servidor, clique na barra de endereço,
   digite powershell e pressione Enter.
5. Execute os comandos abaixo, UM DE CADA VEZ:

   npm install -g firebase-tools
   firebase login
   npm --prefix functions install
   npm --prefix functions test
   firebase deploy --project cuidarmais-e1445 --only "functions:cuidar-pin,firestore:rules"

6. No login, escolha a conta Google que administra cuidarmais-e1445.
7. Se a publicação pedir ativação de APIs necessárias ao Firebase/Cloud
   Functions, leia a solicitação e conclua se estiver de acordo.
8. Aguarde a mensagem de publicação concluída. Devem ser publicadas:
   issuePinAccess, revokePinAccess, loginWithPin, elderAction, syncElderViews.
   Todas usam a região southamerica-east1.

NÃO execute firebase init: a configuração já vem pronta no pacote.
O comando de deploy acima não altera sua hospedagem do GitHub Pages.
Se o PowerShell bloquear npm.ps1, use npm.cmd no lugar de npm e
firebase.cmd no lugar de firebase, sem desativar a segurança do Windows.

Se loginWithPin apresentar erro de assinatura (iam.serviceAccounts.signBlob):
- Veja a conta de serviço em execução da função loginWithPin no Google Cloud.
- Siga a documentação oficial para habilitar IAM Service Account Credentials
  API e conceder a essa conta o papel Service Account Token Creator NO RECURSO
  DA PRÓPRIA CONTA DE SERVIÇO, conforme a necessidade de assinatura.
- Não gere nem envie chaves privadas JSON para o GitHub.
- Envie o erro exato se precisar de orientação nessa etapa.
Documentação: https://firebase.google.com/docs/auth/admin/create-custom-tokens

B. ATUALIZAR O SITE NO GITHUB
1. Entre em https://github.com/kleivsonsilva/CuidarMais
2. Add file → Upload files.
3. Envie TODO O CONTEÚDO da pasta site deste pacote, incluindo icons.
   Não envie a pasta site por fora; index.html deve ficar na raiz do repositório.
4. Confirme em Commit changes.
5. Espere a publicação em Actions ficar verde.
6. Abra o site e pressione Ctrl+Shift+R. No celular, feche todas as abas do site
   e reabra depois da publicação para permitir a atualização do cache.

C. ATIVAR O PIN DE CADA PESSOA
1. Entre com e-mail/senha do responsável.
2. Abra Conta (agora disponível na barra inferior do celular).
3. Localize Acesso por PIN e a pessoa cuidada.
4. Clique em Ativar PIN. Será gerado um NOVO PIN no servidor.
   Os PINs anteriores da versão local não são ativados automaticamente.
5. Anote o PIN ou use Mostrar / Copiar PIN.
6. Saia da conta. No MESMO navegador, escolha a pessoa em Tenho um PIN,
   digite o PIN novo e entre. Não precisa reentrar na conta do responsável.

D. USAR O PIN EM OUTRO CELULAR
1. Na Conta do responsável, use Copiar link de acesso para a pessoa.
2. Envie o link e o PIN à pessoa cuidada.
3. Abra o link NO NAVEGADOR DO CELULAR que será usado e digite o PIN.
4. Depois da primeira abertura, o navegador lembra esse acesso. Basta digitar
   o PIN nas próximas vezes, enquanto o acesso estiver válido.
5. Se limpar o armazenamento do navegador ou trocar de navegador, abra o link
   novamente. O link identifica a pessoa; o PIN confirma o acesso.

E. TESTAR
- Saia da conta do responsável e entre com o PIN novo.
- Confira se aparece SOMENTE a pessoa autorizada e seus medicamentos.
- Confirme uma dose. Depois entre como responsável em outro navegador e confira
  o histórico e o estoque. Confirmar a mesma dose duas vezes não baixa duas vezes.
- No responsável, Gerar novo PIN invalida sessões da versão antiga.
- Desativar acesso impede novas leituras e alterações dessa pessoa.
- Verifique em um celular se Conta está acessível e se não há a barra rotineira
  de mensagens de banco. Erros continuam aparecendo quando precisam de ação.

LIMITES
- Cada acesso dura até 90 dias; gere um novo PIN para renovar.
- Cinco tentativas erradas bloqueiam esse acesso no servidor por 15 minutos.
- Link de acesso e PIN são pessoais. O PIN não revela o e-mail, a conta completa,
  os documentos ou outros perfis da família.
- A pessoa pode ver seus dados, confirmar/não confirmar/adiar dose e pedir ajuda.
  Não pode editar medicamentos, estoque, permissões ou a conta familiar.
- A confirmação de dose por PIN exige internet e validação do servidor.
- Pedidos de ajuda aparecem no app do responsável; não foi criado push quando
  o app está fechado.
- Os horários no servidor usam America/Fortaleza (UTC-3).
- Testes automatizados locais usam simulações de Firebase. A validação visual em
  celular e a validação real das regras/funções no seu projeto ainda são necessárias.
