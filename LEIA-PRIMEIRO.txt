CUIDAR+ — ATUALIZAÇÃO PARA FIREBASE
Projeto: appmais-5b2e4

1. No console https://console.firebase.google.com/project/appmais-5b2e4
   Abra Authentication → Começar → Método de login → E-mail/senha.
   Ative E-mail/senha e salve.
   Google é opcional: ative o provedor Google se quiser usar o botão Google.

2. Authentication → Configurações → Domínios autorizados:
   adicione kleivsonfreitas.github.io (sem https:// e sem /appmais).

3. Firestore Database → Criar banco de dados:
   escolha Standard, banco (default), modo de produção e a localização desejada.
   Se o banco já existir, use o existente.

4. Firestore Database → Regras:
   copie TODO o conteúdo de firestore.rules deste pacote e clique em Publicar.
   As regras limitam cada documento de família ao UID do usuário autenticado.
   Não use regras públicas como "allow read, write: if true".

5. No GitHub https://github.com/KleivsonFreitas/appmais
   Add file → Upload files.
   Arraste TODOS os arquivos DE DENTRO desta pasta e a pasta icons para a RAIZ
   do repositório, no mesmo lugar do index.html atual. Não envie o ZIP.
   Substitua os arquivos existentes e conclua com Commit changes.
   Mantenha Pages: main / (root), conforme já configurado.

6. Espere o GitHub Pages concluir a publicação.
   Abra https://kleivsonfreitas.github.io/appmais/
   No computador, use Ctrl+Shift+R para carregar a nova versão.
   Se o app instalado continuar antigo, feche todas as abas do site e reabra.

7. As contas antigas eram locais: use Criar conta para cadastrar o mesmo e-mail
   no Firebase. O site oferecerá migrar os dados antigos SOMENTE se estiverem
   neste navegador, neste endereço, e o e-mail for o mesmo. Confirme se desejar.
   A senha passa a ser gerenciada pelo Firebase e não é salva no Firestore.
   Dados de outro navegador/endereço/aparelho não são migrados automaticamente.
   Faça Exportar no site antigo antes da atualização, se precisar preservá-los.
   Depois, é possível usar Importar na conta autenticada.

8. Teste: crie um medicamento, aguarde "Salvo no Firebase" e confira o documento
   em Firestore → Dados → families → UID da conta.
   Entre com a MESMA conta em outro navegador/celular: os dados devem aparecer.
   Uma conta diferente deve abrir seus próprios perfis, sem os dados da primeira.

O QUE FOI INTEGRADO
- Login/cadastro Firebase Authentication, recuperação e troca de senha.
- Google via Firebase Authentication, se o provedor estiver habilitado.
- Perfis, medicamentos, estoque, histórico, alertas e configurações no Firestore.
- Atualizações entre aparelhos autenticados na mesma conta.
- Fila de gravação e aviso visível quando há erro ou gravação pendente.
- Controle de versão para não sobrescrever silenciosamente outro aparelho.
- Rascunho por UID neste navegador para recuperar envios interrompidos.
- Cache apenas de arquivos estáticos. Não há login local como alternativa ao Firebase.

LIMITES DESTA ENTREGA
- O PIN é somente um atalho para Modo Simples DEPOIS do login da família.
  Ele não autentica uma pessoa separada e não cria permissão de banco separada.
  Modo Simples é uma interface simplificada da mesma conta familiar.
- Familiares com contas distintas ainda não compartilham dados por convite.
- Alertas, voz e alarme continuam dependentes do app aberto; não foi criado push.
- Documentos de saúde não são enviados ao Storage nesta entrega.
- Esta versão guarda o estado da família em um documento JSON privado, limitado
  a 850 kB. Para históricos maiores, será necessário separar em coleções.
- Se ocorrer edição simultânea, o site avisa do conflito. Exporte o rascunho,
  recarregue os dados da nuvem e confira antes de importar/editar novamente.
- A demo é separada das contas e não envia dados para o Firestore.

VALIDAÇÃO
O código é testado localmente com simulações de Authentication/Firestore.
A criação do banco, ativação dos provedores, publicação das regras e o teste
real no seu projeto dependem de concluir os passos acima no console.
